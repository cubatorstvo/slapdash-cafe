# P5.01 — начало игры и первая звезда

## База

- Исходный `main`: `d2a0d887c3a975fd0727937492d1a96a621b5629`.
- Объём этапа: только чистая новая игра до получения `1★` и передача управления следующей главе.
- Поздняя прогрессия `1★+` сохранена в прежней реализации и вызывается после стартовой главы.

## Фактический путь игрока

| Шаг | Что происходит | Факт прогрессии |
|---|---|---|
| 1. Открытие кафе | До ленточки поток удерживается. После `E` у ленточки кафе открывается и появляется один вводный гость. | `cafe_opened` |
| 2. Первая подача | Вводное блюдо — сосиска. На шеф-стойке реально присутствуют `sauce`, `plates`, `rag`, поэтому первая подача не зависит от награды после самой себя. | `first_manual_served`, `first_sausage_served` |
| 3. Картофель | После успешной сосиски становится известна картошка и её оснащение. Игрок заказывает/устанавливает `pan`; пока нужного оснащения нет или не хватает денег, ручные заказы продолжают приносить деньги на уже освоенной сосиске. | `first_equipment_installed`, затем `first_potato_served` |
| 4. Вино | После успешной картошки открывается вино. Игрок устанавливает `jug` и `cup`; до этого заказы не требуют вина. | `first_wine_served` |
| 5. Ручная практика | После трёх введённых блюд текущая цель — 15 успешно обслуженных вручную гостей. Счётчик не зависит от лаборатории. | `manual_served >= 15` |
| 6. Первая оценка | Дегустатор последовательно просит три стартовых блюда; каждое нужно приготовить на `B` или лучше. Неудачное блюдо повторяется без провала всей проверки. | фактическое `stars >= 1`, сохраняемое как `first_star_earned` |
| 7. Передача | После `1★` открывается `clone_lab`; `clone_growth` остаётся закрытым, пока лаборатория не собрана. Следующая цель существующего `CafeJourney` — базовая сборка лаборатории (`lab_0`). | `clone_lab` открыт, `clone_growth` ещё закрыт |

## Доступность и UI

Единственным источником открытия механик остаются существующие `ProgressionDirector` + `FeatureAccess`.

- Чистая игра: видимы базовые `cafe_core`, `shop_basic`, `stars` и рецепт/оснащение сосиски.
- После первой успешной сосиски: вводится `dish_potato`; `dish_wine` и лаборатория ещё скрыты.
- После успешной картошки: вводится `dish_wine`.
- После успешного вина: все три стартовых блюда известны, но лаборатория всё ещё скрыта.
- После реального получения `1★`: открывается `clone_lab`.
- Известный товар при нехватке денег остаётся видимым и заблокированным с причиной; будущая механика скрыта.
- Книга использует тот же `FeatureAccess`: на чистой игре показывает только сосиску, затем рецепты появляются в той же последовательности.
- HUD продолжает показывать одну текущую цель через `CafeJourney`; отдельный второй граф прогрессии не добавлен.

## Доменные события и сохранение

Новые/используемые факты связаны с завершёнными действиями хоста:

- `cafe_opened` — после фактического перерезания ленточки;
- `manual_served` → `first_manual_served` — после завершённой оплаченной ручной подачи;
- `starter_equipment_installed` → `first_equipment_installed` — после успешной физической установки стартового оснащения на станции №1;
- `starter_dish_served` с `dish=sausage|potato|wine` → `first_<dish>_served` — после успешной ручной подачи соответствующего блюда;
- `first_star_earned` восстанавливается из фактического `stars >= 1` при refresh/save и хранится в `feature_progress`.

`feature_progress` входит в текущее сохранение. Для текущего `SAVE_VERSION` после загрузки сохранённый snapshot повторно применяется как authoritative (`restore(..., true)`), поэтому локальное runtime-состояние не может самовольно расширить сохранённые открытия. Старые форматы остаются на прежнем пути migration/reconcile; специальная миграция старых пользовательских сохранений в этот этап не добавлялась.

`starter_reward`, `cafe_inaugurated`, `inauguration_first_service_pending`, `tutorial_served`, `manual_served` и `stars` остаются частью существующего snapshot прогрессии, поэтому загрузка текущего формата не должна повторять стартовую награду или вводный заказ.

## Изменённые условия 1★

На 0★ `star_requirements()` теперь содержит только:

1. `Лично обслужено: N / 15`;
2. `Освоено стартовых блюд: N / 3`.

`lab_stage` удалён из требований первой звезды. Сама существующая дегустация и правило `B+` для трёх блюд переиспользованы без нового параллельного события оценки.

- `tests/test_first_star.gd` — целевой путь 0★ → ленточка → сосиска → установка оснащения → картофель → вино → 15 ручных подач → дегустация → `1★` → handoff к `lab_0`; также проверяет отсутствие денежного тупика и current-format authoritative snapshot.
